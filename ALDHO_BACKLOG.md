# ALDHO Backlog

Рабочий план разработки сайта бренда одежды ALDHO.

## Goal

Собрать минималистичный, mobile-first сайт бренда одежды ALDHO, где футболка всегда остаётся главным объектом внимания, а пользователь приходит к заказу через WhatsApp.

## Product Principles

- Белый фон, чистый минимализм, сильная типографика
- Футболка и принт всегда в центре внимания
- Интерфейс не должен выглядеть как шаблонный интернет-магазин
- Главная задача сайта — довести пользователя до заказа
- Анимации усиливают опыт, но не ломают функциональность
- Mobile-first с первого этапа
- На слабых устройствах должен быть упрощённый fallback

## Core User Flow

1. Пользователь попадает на главную страницу
2. Понимает стиль бренда и качество продукта
3. Переходит в коллекцию
4. Открывает персонажа / тему
5. Выбирает дизайн, размер, цвет
6. Добавляет товар в корзину или сразу заказывает
7. Завершает заказ через WhatsApp

## Project Architecture

Бэкенд не нужен.

Данные:
- контент и товары хранятся внутри проекта
- корзина работает через localStorage
- заказ оформляется через WhatsApp-ссылку с автотекстом

Основные маршруты:
- /
- /collection

Базовая структура проекта:
- app/
- components/
- data/
- lib/
- types/
- public/

## Delivery Strategy

Проект делается в 3 слоя:

1. Foundation
- структура
- дизайн-система
- layout
- данные
- маршруты

2. MVP
- главная
- коллекция
- страница персонажа
- корзина
- WhatsApp checkout

3. Motion Layer
- scroll-driven анимации
- hero motion
- reveal effects
- performance fallback

## Planning Depth Rules

Планируем не всё одинаково глубоко.

Что фиксируем заранее жёстко:
- product goals
- user flow
- routes
- high-level architecture
- data model на верхнем уровне
- delivery order
- constraints
- fallback strategy

Что планируем только как рабочую гипотезу:
- сложные анимации
- scroll-driven mechanics
- точную motion implementation
- тяжёлые visual effects
- детали risky UI patterns

Правило:
- стабильные части фиксируем заранее
- рискованные части подтверждаем через prototype и тестирование
- если тесты ломают гипотезу, меняем технический подход без ломки общего плана

## Execution Rules

Для терминального агента:
- работать строго по фазам сверху вниз
- не перепрыгивать в motion, пока не готов MVP layer
- не переусложнять implementation раньше времени
- делать маленькими шагами
- после каждого смыслового шага проверять lint/build
- если найден рискованный технический блок, сначала делать prototype, потом принимать окончательное решение

## Current Recommended Track

Текущий режим работы:
1. Завершить foundation полностью
2. Перейти в Phase 2 Data Model
3. Потом делать только Homepage MVP
4. Только после этого переходить в collection routes и cart

Сейчас не уходить в:
- full motion integration
- сложный hero pipeline
- production video integration
- финальные scroll scenes

Результат:

## Phase 5. Collection Detail
--------------------------------------------------

Цель:
собрать страницу персонажа / темы и показать конкретные дизайны.

Задачи:
1. Создать динамический маршрут /collection/[slug].
2. Подтянуть данные выбранной темы / персонажа.
3. Выводить активный дизайн:
   - название
   - описание принта
   - цену
   - цвета
   - размеры
4. Добавить CTA:
   - В корзину
   - Заказать через WhatsApp
5. Добавить раскрывающийся блок:
   - материал
   - уход
   - производство
   - обмен
6. Подготовить sticky CTA для мобайла.
7. Сделать базовую narrative-структуру страницы без сложной motion-логики.

UX direction для product page:
- футболка остаётся главным центральным объектом
- выбор цвета делается через визуальные swatches
- при выборе цвета меняется visual товара
- размер выбирается рядом с основным CTA
- CTA заказа остаётся в зоне быстрого доступа
- на десктопе допустим вертикальный color picker рядом с футболкой
- на мобиле использовать компактные раскрывающиеся селекторы справа или под товаром
- mobile color selector показывает только swatch + стрелку вниз без текста
- mobile size selector показывает только размер + стрелку вниз без лишнего текста
- по нажатию каждый selector плавно раскрывает варианты вниз
- финальную реализацию UI подтвердить во время разработки и тестирования

Результат:
ключевая продуктовая страница уже рабочая и понятная.

  - одна feature branch
